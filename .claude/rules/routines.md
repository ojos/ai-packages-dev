# ルーティン（無人の実行）の依頼文

地図（`.github/project-ai-rules.md`）の「常時適用」の詳細です。

## 無人実行の 5 点

無人で動くもの（クラウドのルーティンなど）は、人が見ていないあいだに書き込みを行います。止める人がいない状態で動かすには、動く前に次の 5 点が揃っている必要があります（Anthropic の「Let Claude run without you」。#669 の 2-6、#713）。

| 項目 | 書くこと |
|---|---|
| 完了の定義 | 何が起きていれば、その回が終わったと言えるか（書き込み先と件数） |
| 自分で検証する手段 | ルーティン自身が回して合否を得るコマンド。`bash scripts/….sh` の形で書く |
| 触れる範囲 | 書き込み先と参照先。issue / PR は番号で列挙する |
| 上限 | 1 回あたりの上限（書き込みの件数・手番・時間のどれか）を「1 回の実行で…」「1 回あたり…」の形で、単位の付いた数で書く。実行の頻度も書く |
| 最終的に承認する人 | ルーティンの出力を受けて、変更を決める人。ルーティン自身ではない |

各依頼文（`docs/routines/*.md`）は、`## 無人実行の 5 点` の節に、この 5 つを行に持つ表（`| 項目 | 宣言 |`）を置きます。ルーティンに貼る文は `## 依頼文` で始まる節に置き、`禁止:` の箇条書きを持たせます。

## 検査が確かめること・確かめないこと

`tests/test-routine-preconditions.sh` が、`docs/routines/*.md` のすべてを確かめます。新しいルーティンを足して 5 点を書き忘れると、この検査で落ちます。

- **確かめる:** 検証のコマンドのスクリプトが実在すること。依頼文の節に出てくるすべての `#N`（別のリポジトリの `owner/repo#N` は別のものとして）が、触れる範囲に列挙されていること。上限が 1 回あたりの上限を単位の付いた数で書いていること（実行の頻度だけでは通さない）。依頼文が `禁止:` の直後に、否定（「〜ない」）で書いた箇条書きを持つこと。
- **区別しない:** 範囲の中の書き込み先と、読むだけの参照。依頼文のどの `#N` が書き込みかは、機械では判定できないためです。範囲の外の番号は、読むだけでも落とします。
- **確かめない:** 完了の定義と最終的に承認する人の中身、検証のコマンドが完了の定義を本当に確かめられるか。欄が空でないことだけを見ます。中身を機械で確かめられない欄を、それ以上機構化すると、書いたかどうかの儀式だけが残るためです（共通規範 12 章「機構化の判断基準」）。中身はレビューで確かめます。
- **実行時には強制しません。** クラウドのルーティンは、こちらから起動の前に止める手段がありません。上限の数は宣言で、守らせるのは依頼文です。

「最終的に承認する人」の欄は、ルーティンの出力が承認の根拠にならないこと（共通規範 12 章「承認の根拠にできるもの」）を、ルーティンごとに誰が受け止めるかとして書く欄です。
